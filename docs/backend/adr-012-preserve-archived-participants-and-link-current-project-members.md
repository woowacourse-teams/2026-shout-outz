# ADR-012: 아카이브 참여자를 보존하면서 현재 프로젝트 멤버로 연결

### 결정일 및 결정자
- 결정일: 2026.08.19
- 결정자: 조상준(샤를), 최재영(재키), 박다혜(라이)
- 작성자: 조상준(샤를)

## 상태 (Status)

수락됨 (Accepted)

대체된 경우: 해당 없음

## 컨텍스트 (Context)

과거 기수의 프로젝트(2기부터 7기를 지칭한다. 이하 동일)는 허가받은 프로젝트에 한에서, [https://github.com/woowacourse-teams](https://github.com/woowacourse-teams) Github Repository를 기반으로 수집한 정보이다. 따라서, 해당 프로젝트들은 Dropit 회원이 아닌 참여자 정보도 함께 보존해야 한다. 아카이브 당시의 GitHub 계정 ID, 로그인 이름, 표시 이름, 프로필 이미지와 표시 순서는 당시 데이터를 기준으로 한 스냅샷이다.

과거 기수 프로젝트 참여자가 이후 Dropit에 가입하면 해당 사용자를 현재 서비스의 사용자로 연결해야 한다. 그래야 크루별 프로젝트 모아보기나 사용자 페이지와 같은 기능에서 현재 회원 정보를 활용할 수 있다.

과거 기수 참여자의 스냅샷을 삭제하고 ‘현재 프로젝트 멤버’ 테이블로 데이터로 옮기면 원본 수집 정보가 사라진다. 반대로 스냅샷만 갱신하면 프로젝트 멤버를 조회할 때 아카이브 참여자와 현재 회원을 매번 함께 조회해야 한다.

## 결정 (Decision)

과거 기수 프로젝트의 참여자가 Drop it에 가입하면 아카이브 참여자 테이블(`woowa_archived_project_members`) 행의 `matched_user_id`를 채우고, 동시에 `project_members`에 현재 사용자와 프로젝트의 연결을 추가한다.

아카이브 참여자 테이블(`woowa_archived_project_members`)의 원본 스냅샷은 삭제하거나 현재 프로필 정보로 덮어쓰지 않는다.

`project_members`는 현재 Dropit 회원을 기준으로 프로젝트 멤버를 조회하는 데 사용하고, 아카이브 참여자 테이블(`woowa_archived_project_members`)은 수집 당시의 정보를 보존하는 데 사용한다. 즉, `woowa_archived_project_members`에는 미래 시점에 새로운 행 INSERT가 존재하지 않는다.

두 테이블의 변경은 하나의 트랜잭션으로 처리한다.

## 결과 (Consequences)

**긍정적 영향**: 프로젝트별 현재 멤버 조회는 `project_members`를 기준으로 단순화할 수 있다. 크루별 모아보기에서도 현재 회원과 아카이브 참여자를 각각의 목적에 맞게 조회할 수 있다. 아카이브 당시의 참여자 정보와 현재 회원 연결 정보를 모두 보존한다.

**부정적 영향**: 하나의 연결이 두 테이블에 저장되므로 회원가입 매칭 시 두 쓰기 작업을 함께 관리해야 한다. 프로젝트 멤버를 표시할 때 현재 멤버와 아카이브 스냅샷을 중복으로 노출하지 않도록 조회 규칙이 필요하다. 매칭 실패나 중복 가입을 처리하는 보정 작업이 필요하다.

**중립적 영향**: 어떤 OAuth 식별자를 사용해 매칭할지와 매칭 시점을 별도로 정의한다. 사용자가 계정을 연결 해제하거나 계정 상태가 변경될 때 `matched_user_id`와 `project_members`를 어떻게 처리할지 후속 정책으로 정한다.

## 검토한 대안 (Options Considered)

**대안 1**: 아카이브 참여자 행을 삭제하고 `project_members`에만 추가한다. 현재 멤버 조회는 단순해지지만, 아카이브 당시의 원본 정보가 사라지고 과거 수집 데이터의 의미가 훼손되므로 선택하지 않았다.

**대안 2**: 아카이브 참여자 행의 `matched_user_id`만 채우고 `project_members`에는 추가하지 않는다. 원본 스냅샷은 보존할 수 있지만 현재 멤버 기능과 크루별 조회에서 두 테이블을 함께 다뤄야 하므로 선택하지 않았다.
