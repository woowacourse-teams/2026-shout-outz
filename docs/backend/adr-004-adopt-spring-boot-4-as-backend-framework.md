# ADR-004: Spring Boot 4를 백엔드 프레임워크로 채택

### 결정일 및 결정자
- 결정일: 2026.08.19
- 결정자: 조상준(샤를), 최재영(재키), 박다혜(라이)
- 작성자: 최재영(재키)

## 상태 (Status)

수락됨 (Accepted)

## 컨텍스트 (Context)

Spring 기반 서버를 애플리케이션 및 API 계층으로 사용하기로 결정했기에, 사용할 Spring Boot 버전을 선택해야 한다.

프로젝트 시작 시점인 2026년에는 Spring Boot 3 계열의 마지막 마이너 버전인 3.5.x의 OSS 지원이 종료되었다. 3.5.16이 마지막 OSS 릴리스이며, 이후 지속적인 OSS 지원을 받으려면 Spring Boot 4 계열로 전환해야 한다.

Drop-it은 신규 프로젝트이므로 기존 Spring Boot 3 코드나 라이브러리와의 호환성을 유지해야 하는 레거시 제약도 없다.

따라서 지원이 종료된 3 계열로 새 프로젝트를 시작한 뒤 다시 메이저 업그레이드를 수행하기보다, 현재 지원되는 Spring Boot 4를 기준으로 시작하는 것이 적합하다고 판단했다.

## 결정 (Decision)

Drop-it 백엔드는 **Spring Boot 4 계열**을 사용한다.

프로젝트 시작 시점의 기준 버전은 `Spring Boot 4.1.0`으로 한다. 정확한 패치 버전은 이후 빌드 설정에서 관리한다.

## 결과 (Consequences)

**긍정적 영향**: 현재 OSS 지원이 제공되는 Spring Boot 계열을 기준으로 개발할 수 있다. 지원이 종료된 3 계열로 시작한 뒤 가까운 시점에 메이저 업그레이드를 수행해야 하는 비용을 피할 수 있다.

**부정적 영향**: Spring Boot 4에서 변경된 API와 의존성 생태계를 기준으로 개발해야 하며, 사용하는 외부 라이브러리가 Spring Boot 4와 호환되는지 확인해야 한다. Spring Boot 4는 메이저 버전 변경으로 여러 의존성과 API에도 변경이 있기 때문에 관련 자료나 라이브러리 사용 시 버전 확인이 필요하다.

**중립적 영향**: Java 버전, 세부 Spring 모듈 및 배포 환경은 별도의 결정이나 프로젝트 설정에서 관리한다.

## 검토한 대안 (Options Considered)

**대안 1**: Spring Boot 3.5 계열을 사용한다. 기존 학습 자료와 사용 사례가 많고 익숙한 생태계를 사용할 수 있다는 장점이 있다. 그러나 프로젝트 시작 시점에 이미 OSS 지원이 종료된 버전이며, 신규 프로젝트에서 이를 선택해야 할 레거시 제약도 없다. 이후 Spring Boot 4로의 메이저 업그레이드가 다시 필요해지므로 선택하지 않았다.
