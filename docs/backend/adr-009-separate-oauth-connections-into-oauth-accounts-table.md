# ADR-009: OAuth 연결 정보를 oauth_accounts 테이블로 분리

### 결정일 및 결정자
- 결정일: 2026.08.19
- 결정자: 조상준(샤를), 최재영(재키), 박다혜(라이)
- 작성자: 최재영(재키)

## 상태 (Status)

수락됨 (Accepted)

## 컨텍스트 (Context)

현재 Drop-it의 주요 로그인 수단은 GitHub OAuth이며, 우테코와 개발자 중심의 현재 사용자 층에서는 GitHub만으로도 충분할 수 있다.

하지만 향후 우테코 외부 사용자까지 서비스가 확장될 경우 모든 사용자가 GitHub 계정을 가지고 있거나 GitHub 로그인을 선호한다고 가정하기 어렵다. Google, Kakao 등 다른 OAuth 제공자를 추가할 가능성을 열어둘 필요가 있다.

OAuth 정보를 `users`에 직접 저장하면 특정 제공자에 사용자 모델이 결합되고, 새로운 OAuth 제공자를 추가할 때 사용자 구조를 변경해야 한다.

## 결정 (Decision)

Drop-it 내부 사용자는 `users`, 외부 OAuth 계정과의 연결은 `oauth_accounts`에서 관리한다.

한 사용자는 여러 OAuth 계정을 연결할 수 있는 구조로 두며, 새로운 OAuth 제공자가 추가되더라도 `users`의 구조는 변경하지 않는다.

외부 OAuth 계정의 식별에는 변경 가능한 로그인 이름이 아니라 제공자가 발급한 안정적인 계정 ID를 사용한다. 제공자 프로필 이미지 등 OAuth 제공자에 종속된 정보 역시 `oauth_accounts`에서 관리한다.

## 결과 (Consequences)

**긍정적 영향**: 내부 사용자 모델이 특정 OAuth 제공자에 종속되지 않는다. GitHub 외의 로그인 수단을 추가할 때 기존 사용자 테이블을 변경하지 않고 확장할 수 있다.

**부정적 영향**: 사용자와 OAuth 계정 연결을 별도로 관리해야 하며, 여러 OAuth 계정의 연결/해제 및 동일 계정 중복 연결에 대한 정책이 필요하다.

**중립적 영향**: 실제로 추가할 OAuth 제공자와 추가 시점은 현재 결정하지 않는다. 프로필 정보의 동기화 정책 역시 필요한 시점에 별도로 결정한다.

## 검토한 대안 (Options Considered)

**대안 1**: GitHub OAuth만 지원하고 GitHub 계정 정보를 `users`에 저장한다. 현재 요구사항에는 가장 단순하지만, 다른 로그인 수단을 추가할 경우 사용자 모델을 다시 변경해야 하므로 선택하지 않았다.

**대안 2**: OAuth 제공자가 추가될 때마다 `users`에 Google, Kakao 등의 제공자별 컬럼을 추가한다. 별도 테이블은 필요 없지만 제공자가 늘어날수록 사용자 모델에 외부 인증 정보가 누적되고 스키마 변경이 반복되므로 선택하지 않았다.
