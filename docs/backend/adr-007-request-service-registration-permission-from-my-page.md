# ADR 007: 서비스 등록 권한 신청은 마이페이지에서 제공한다

## 상태 (Status)

수락됨 (Accepted)

## 컨텍스트 (Context)

현재 Drop-it은 모든 사용자가 자유롭게 서비스를 등록하는 구조가 아니라, 승인된 사용자에게만 서비스 등록 권한을 제공한다. 따라서 사용자가 권한이 없다는 사실을 알았을 때 권한 신청으로 이어질 수 있는 진입점을 제공해야 한다.

서비스를 등록할 때마다 권한을 확인하고 신청하게 하거나, 최초 로그인 시 한 번만 신청을 요구하는 방식은 사용자의 일반적인 서비스 이용 흐름을 방해할 수 있다. 반면 최초 가입 이후 안내하고, 이후에는 사용자가 필요할 때 다시 접근할 수 있는 경로를 제공하면 권한 신청과 일반 이용을 분리할 수 있다.

## 결정 (Decision)

서비스 등록 권한 신청 기능은 마이페이지에서 제공한다.

최초 가입 이후에는 팝업으로 서비스 등록 권한 신청 경로를 안내한다. 사용자가 안내를 닫거나 나중에 신청하기로 한 경우에도 마이페이지에서 관리자에게 권한을 신청할 수 있도록 한다.

서비스 등록 시점마다 권한 신청 화면을 강제로 노출하지 않는다. 사용자가 실제로 등록을 시도할 때 권한이 없으면 마이페이지의 신청 경로를 안내할 수 있지만, 신청 기능의 기준 진입점은 마이페이지로 유지한다.

## 결과 (Consequences)

**긍정적 영향**: 최초 가입 직후 사용자에게 권한 신청 기능을 알릴 수 있다. 사용자가 안내를 놓쳐도 마이페이지에서 다시 신청할 수 있다. 서비스 탐색과 권한 신청 흐름을 분리해 일반적인 서비스 이용을 방해하지 않는다.

**부정적 영향**: 사용자가 권한 신청 경로를 직접 찾아야 할 수 있다. 마이페이지에 신청 상태, 신청 가능 여부, 처리 결과를 표시하는 UI와 API가 필요하다.

**중립적 영향**: 관리자 승인 방식, 승인 결과를 승인 기록 테이블에 반영하는 시점, 신청 취소·재신청 정책은 별도로 결정한다. 승인 결과에 따른 서비스 등록 가능 여부는 [ADR 006](./adr-006-model-service-registration-permission.md)의 기준을 따른다.

## 검토한 대안 (Options Considered)

**대안 1**: 서비스 등록을 시도할 때마다 권한 신청을 받는다. 권한이 필요한 순간에는 신청을 안내할 수 있지만, 서비스 등록 흐름마다 권한 절차가 개입되어 일반 이용 경험을 방해할 수 있으므로 선택하지 않았다.

**대안 2**: 최초 로그인 시 한 번만 권한 신청을 받는다. 초기 안내는 단순하지만 사용자가 신청을 미루거나 나중에 권한이 필요해진 경우 다시 접근할 수 있는 경로가 부족하므로 선택하지 않았다.
