# ADR 004: Gradle Wrapper를 빌드 도구로 채택한다

## 상태 (Status)

수락됨 (Accepted)

## 컨텍스트 (Context)

백엔드 프로젝트는 의존성 관리, 컴파일, 테스트, 패키징을 반복적으로 수행하므로 팀이 동일한 빌드 환경을 사용하도록 빌드 도구를 정해야 한다.

후보로 Maven과 Gradle을 검토했다. 팀은 XML 중심으로 설정하는 Maven보다 코드 기반으로 빌드 설정을 작성할 수 있는 Gradle이 가독성과 확장성 측면에서 프로젝트에 적합하다고 판단했다.

## 결정 (Decision)

Drop-it 백엔드는 Gradle을 사용하고, Gradle Wrapper로 빌드 도구 버전을 고정한다. 현재 기준 버전은 Gradle Wrapper 9.6.0이다.

의존성 관리, 애플리케이션 빌드, 테스트 실행은 저장소에 포함된 Wrapper를 기준으로 수행한다. 개발자별로 설치된 전역 Gradle 버전에 빌드 결과가 의존하지 않도록 한다.

## 결과 (Consequences)

**긍정적 영향**: 빌드 설정을 코드 기반으로 관리할 수 있어 설정을 읽고 확장하기 쉽다. Wrapper를 사용하면 개발환경과 CI에서 동일한 Gradle 버전을 사용할 수 있다. 의존성 관리와 테스트 실행을 하나의 빌드 흐름으로 통합할 수 있다.

**부정적 영향**: Gradle DSL과 생명주기를 학습해야 한다. 빌드 스크립트와 플러그인이 복잡해지면 빌드 시간이 늘어나거나 설정을 이해하기 어려워질 수 있다.

**중립적 영향**: Gradle 버전 업그레이드는 Spring Boot와 플러그인 호환성을 확인한 뒤 진행한다.

## 검토한 대안 (Options Considered)

**대안 1**: Maven을 사용한다. Java 생태계에서 널리 사용되고 규칙이 명확하다는 장점이 있지만, 이 프로젝트에서는 코드 기반 빌드 설정의 가독성과 확장성을 우선하기 위해 선택하지 않았다.
