# ADR 008: OAuth 연결 정보를 oauth_accounts 테이블로 분리한다

## 상태 (Status)

수락됨 (Accepted)

대체된 경우: 해당 없음

## 컨텍스트 (Context)

현재 주요 로그인 수단은 GitHub OAuth다. 그러나 GitHub 계정이 없는 사용자가 댓글이나 북마크 기능을 사용하거나, 다른 OAuth 제공자를 선호할 가능성을 배제할 수 없다.

OAuth 제공자마다 계정 식별자와 프로필 정보의 형식이 다르다. 특히 제공자가 발급한 안정적인 계정 ID와 사용자가 변경할 수 있는 로그인 이름을 구분해야 한다. OAuth 프로필 이미지와 마지막 동기화 시각처럼 제공자에 종속된 정보도 내부 사용자 계정 정보와 분리할 필요가 있다.

## 결정 (Decision)

OAuth 제공자 연결 정보를 `oauth_accounts` 테이블로 분리한다.

`users` 테이블은 Dropit 내부 사용자를 식별하고, `oauth_accounts` 테이블은 사용자의 OAuth 제공자별 연결 정보를 관리한다. OAuth 계정을 식별할 때는 제공자가 발급한 안정적인 계정 ID를 사용하고, 제공자의 로그인 이름을 식별 기준으로 사용하지 않는다.

OAuth 제공자 프로필 이미지, 마지막 동기화 시각, 마지막 로그인 시각과 같은 제공자별 정보는 `oauth_accounts`에 저장한다. 새로운 OAuth 제공자를 추가할 때는 `users` 테이블의 구조를 변경하지 않고 새로운 제공자 연결을 추가한다.

## 결과 (Consequences)

**긍정적 영향**: GitHub 외 OAuth 제공자를 추가하기 쉬워진다. 제공자별 식별자와 프로필 동기화 정보를 독립적으로 관리할 수 있다. 내부 사용자 식별자와 외부 OAuth 식별자를 분리해 인증 제공자 변경의 영향을 줄일 수 있다.

**부정적 영향**: 로그인 사용자 정보를 조회할 때 OAuth 연결 정보와 조인이 필요할 수 있다. 여러 OAuth 계정 연결, 연결 해제, 동일 사용자의 중복 연결을 처리하는 정책을 추가로 구현해야 한다. 제공자 프로필 변경을 동기화하는 로직도 관리해야 한다.

**중립적 영향**: 지원할 OAuth 제공자의 종류와 추가 시점은 별도로 결정한다. 제공자별 계정 연결의 유일성, 연결 해제 가능 여부, 프로필 이미지 동기화 주기는 애플리케이션 정책으로 정한다.

## 검토한 대안 (Options Considered)

**대안 1**: OAuth 제공자별 컬럼을 `users` 테이블에 추가한다. 현재 GitHub만 지원할 때는 구현이 단순하지만, 제공자를 추가할 때마다 `users` 스키마를 변경해야 하고 제공자별 정보가 한 테이블에 섞이므로 선택하지 않았다.

**대안 2**: GitHub 전용 인증 정보를 `users` 테이블에 저장한다. 초기 구현 비용은 낮지만 다른 OAuth 제공자를 추가할 때 계정 식별과 프로필 정보를 다시 설계해야 하므로 선택하지 않았다.
