# TADD Flow

AI가 테스트와 구현을 동시에 결정하지 않도록 한다.

기본 흐름은 다음과 같다.

```text
요구사항
   ↓
인터페이스 정의
   ↓
AI 테스트 작성
   ↓
개발자 테스트 검증
   ↓
AI headless 로직 구현
   ↓
테스트 실행
   ↓
개발자 코드 검토
```

---

1. 개발자가 요구사항과 현재 구현 맥락을 정리한다.
2. 구현 전에 함수 시그니처, props, 반환값 등 외부에서 사용되는 인터페이스를 먼저 정의한다.
    1. 인터페이스가 사전에 정의되어 있지 않다면 다음 단계로 절대 넘어가지 않는다.
3. 정의된 요구사항과 인터페이스를 기준으로 AI가 테스트를 작성한다.
4. 개발자가 테스트가 실제 요구사항을 올바르게 표현하고 있는지 확인한다.
5. 검증된 테스트와 인터페이스를 기준으로 AI가 headless 로직과 동작을 구현한다.
6. 테스트를 실행한다.
7. 개발자가 구현 결과와 테스트 결과를 검토한다.
8. 마크업과 스타일링은 개발자가 직접 작성한다.

중요한 원칙은 **AI가 테스트와 구현을 동시에 결정하지 못하도록 테스트를 먼저 사람에게 검증받는 것**이다.

또한 구현 전에 외부 인터페이스를 먼저 정의해 AI가 구현 과정에서 컴포넌트 API나 함수 계약까지 임의로 결정하지 않도록 한다.

AI에 맡기는 구현 범위는 우선 headless 로직을 중심으로 제한한다.
